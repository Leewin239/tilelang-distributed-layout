# 四卡 H100 实验结果摘要

基线：TileScale `71e71457d40ed6e6a2dad297936bfdbff21d104b` 的 specialized 原版实现。BF16；四卡 GPU 0–3；全部列出的正式对照均通过 PyTorch 参考值正确性检查。加速比定义为原版 GPU 时间除以新版 GPU 时间；每个数字是一批七轮 ABBA 交错配对的中位数。

## 联合使用 AG+GEMM 与 GEMM+RS 的序列并行层

| token / hidden / FFN | MLP 子层，两批 | 完整 decoder block，两批 |
|---|---:|---:|
| 1024 / 1024 / 4096 | 1.106×、1.091× | 1.094×、1.097× |
| 2048 / 2048 / 8192 | 1.082×、1.089× | 1.070×、1.061× |

MLP 与完整 block 均采用普通 CUDA event 单次前向计时。完整 block 的注意力 QKV 和输出投影也使用 TileScale 原版融合算子作为基线。2048 档部分单轮低于 1.06×，两批中位数刚过目标线；共享服务器测试不能代替独占资源验证。

## 当前方案的算子区域

| 全局 GEMM 形状 | AG+GEMM+GELU，两批 | GEMM+RS+残差，两批 |
|---|---:|---:|
| 512³ | 原版默认 AG 不支持精确形状 | 1.195×、1.207× |
| MLP 1024 / 1024 / 4096 | 1.002×、1.024× | 1.254×、1.279× |
| MLP 2048 / 2048 / 8192 | 1.050×、1.090× | 1.041×、1.043× |
| 4096³ | 1.136×、1.144× | 1.053×、1.047× |

“MLP”行是实际非立方形状。AG 区域两边都产出 GELU 后的激活；RS 区域两边都产出加残差后的结果，所以能公平比较中间数据物化位置。512³ RS 采用 10 次调用 CUDA Graph 稳态单次均值，其余区域采用普通 CUDA event 单次前向；不同计时口径的绝对耗时不可横比。4096³ RS 若机械采用小形状的 K128 分块，首批降至 0.897×；表中选择原版分块并保留残差直写。

## GEMM+AllReduce 单独路径

| 全局 GEMM 形状 | 原版/新版两批 |
|---|---:|
| 1024³，64×128×64 tile | 1.097×、1.096× |
| 2048³，64×256×64 tile | 1.086×、1.083× |

AR 的 TP MLP 下投影和完整 block 是单独路径，不能与上面的 SP 层级加速比相加。直接远端原子写是研究候选，在更大输出上并不稳定优于原版；正式 AR 结果采用 TileScale 多播归约内调整计算 tile 的版本。

这些都是代表性合成输入的前向实验，不是实际模型训练或端到端推理结果。原始日志留在实验服务器，未纳入仓库。
